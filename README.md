# 能量少年研学 · 拼团小程序

基于**微信小程序 + 微信云开发**（云函数 / 云数据库 / 云存储）实现的研学拼团系统。

核心业务闭环：

```
提交成团申请 → 管理员审核 → 自动建团 → 团长分享 → 成员报名参与
      → 付款（微信支付 / 线下凭证）→ 管理员确认收款 → 台账统计与导出
```

> **职责边界：系统止于「店家确认收款」。**
> 不做分账、不做子账户、不做自动打款、不做自动结算。后续的线下分钱不纳入本系统。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | 微信小程序原生开发（无框架、无 npm 依赖） |
| 后端 | 微信云开发云函数，Node.js 16.13 |
| 数据库 | 云开发文档型数据库（类 MongoDB，无需预先建表） |
| 文件存储 | 云开发云存储（付款凭证、收款码、头像） |
| 支付 | 云开发 `cloud.cloudPay`（免签名、免证书） |
| 基础库 | 3.17.3 |

选型上刻意保持**零构建、零依赖**：小程序端纯原生，云函数只依赖 `wx-server-sdk`，克隆下来用微信开发者工具打开即可运行，不需要 `npm install` 或打包流程。

## 架构设计

### 两端分离 · 两个云函数

| 云函数 | 面向 | 职责 |
| --- | --- | --- |
| `ptApi` | 普通用户 / 团长 | 登录、成团申请、参与拼团、下单支付、提交付款凭证、个人资料 |
| `ptAdmin` | 管理员 | 审核成团申请、拼团管理、确认收款、台账统计与导出、管理员管理、黑名单 |

### 鉴权模型

系统**没有账号密码**。所有接口的身份都来自云函数内的：

```js
const wxContext = cloud.getWXContext();
const OPENID = wxContext.OPENID;
```

`OPENID` 由微信服务端在调用链路中注入，**客户端无法伪造**。管理员身份 = `pt_admins` 集合白名单（`enabled: true`），角色分为 `superadmin` > `admin` > `leader` > `user`。

### 数据访问边界

**小程序端不直接读写数据库**，全部数据访问都经过云函数。因此数据库集合权限保持默认的「仅创建者可读写」即可 —— 云函数持有管理员权限，不受该限制约束。

他人上传的图片（付款凭证等）一律由云函数通过 `cloud.getTempFileURL` 转为临时链接后再返回，不直接把 `fileID` 交给非上传者。

### 接口约定

云函数统一入参 `{ action, ...params }`，统一返回 `{ ok, msg, data }`。

## 快速开始

全程约 15 分钟，不需要写任何服务器代码。

### 1. 导入项目

1. 安装[微信开发者工具（稳定版）](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 「导入项目」→ 目录选择本项目**根目录**（含 `project.config.json` 的那一层）
3. AppID 填 `project.config.json` 中已有的，或换成你自己的小程序 AppID

### 2. 开通云开发

1. 开发者工具顶部点「**云开发**」按钮
2. 按提示开通，创建一个环境（名字随意，如 `pintuan-prod`）
3. 进入「云开发控制台 → 设置 → 环境」，复制**环境 ID**（形如 `xxx-3g8xxxxx`）

> **⚠️ 计费提醒**：免费体验版环境在小程序**正式发布后第 15 天到期**，到期后进入停服隔离，不转付费即**销毁环境、数据全部丢失**。
> 开发测试用免费版没问题，但**正式发布前务必升级到个人版（¥19.9/月）**。本项目用量极小（云函数 13.3 资源点/万次调用、数据库 200 资源点/万次），个人版绰绰有余。

### 3. 填入环境 ID

编辑 `miniprogram/app.js`：

```js
globalData: {
  envId: '你的环境ID',   // ← 换成第 2 步复制的那串
  ...
}
```

**漏掉这步会一直弹「云端未连接」。**

### 4. 部署云函数

**4.1 先给云函数根目录绑定环境**（漏了会报 `请在 cloudfunctionRoot 选择一个云环境`）

左侧文件树 → **右键最外层的 `cloudfunctions` 目录**（不是里面的 `ptApi`）→「选择云开发环境」→ 选中刚创建的环境。

绑定成功后，文件树上 `cloudfunctions` 后面的「未选…」会消失。**这一步必须在上传之前完成。**

**4.2 逐个上传**

- 右键 `cloudfunctions/ptApi` → **「上传并部署：云端安装依赖」**
- 右键 `cloudfunctions/ptAdmin` → **「上传并部署：云端安装依赖」**

每个约需 30 秒 ~ 2 分钟，控制台出现「上传成功」即完成。

> **以后只要改动了 `cloudfunctions/` 里的代码，都必须重新执行这一步。** 小程序「上传代码」只更新前端，不会更新云函数。

### 5. 创建数据库集合

云函数内已实现首次调用时**自动建集合**的逻辑，但部分环境 / 套餐下 `createCollection` 可能没有权限。若自动建表失败，在「云开发控制台 → 数据库」手动新建以下集合（名字必须完全一致，区分大小写）：

`pt_users`、`pt_applications`、`pt_groups`、`pt_members`、`pt_pay_configs`、`pt_admins`、`pt_config`、`pt_blacklist`

> **新建后是空集合，这是正常的。**
> - 不需要手动添加字段：文档型数据库没有固定表结构，字段在写入第一条数据时自动产生
> - 不需要添加初始记录

### 6. 设置第一个管理员

系统无账号密码，第一个管理员通过自助入口产生。**仅限开发测试阶段使用：**

1. 在云开发控制台 → 云函数 → `ptApi` → **配置 → 环境变量**，添加 `ALLOW_SELF_GRANT = 1`
2. 重新部署 `ptApi`（环境变量改动后重新部署一次最稳妥）
3. 用你自己的微信打开小程序 → 「我的」→「**测试管理员功能**」
4. 能看到管理端工作台即成功

> **该入口默认关闭**，且当 `pt_admins` 集合已存在管理员时会自动失效。上线前在控制台**删掉 `ALLOW_SELF_GRANT`** 即可永久关闭，无需改动代码。

### 7. 接入微信支付（可选）

支付链路代码已完整实现，只差一个商户号：

1. 申请微信支付商户号
2. **云开发控制台 → 设置 → 全局设置 → 添加商户号**，并在商户号管理员手机上确认授权
3. 编辑 `cloudfunctions/ptApi/index.js` 顶部，把 `const SUB_MCH_ID = ''` 填成你的商户号（字符串）
4. 右键 `ptApi` → **上传并部署**

商户号未配置时，点「微信支付」会提示「正在开通中」，此时成员仍可走**线下付款 + 上传凭证**由管理员人工核实。

## 环境变量

在「云开发控制台 → 云函数 → 对应函数 → 配置 → 环境变量」中设置。

| 变量 | 所属云函数 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ALLOW_SELF_GRANT` | `ptApi` | 未设置（= **关闭**） | 设为 `1` 时开放「测试管理员功能」自助授权。**上线前必须删除** |

环境变量采用 **fail-closed** 设计：未配置即视为关闭，避免遗忘导致测试入口残留在生产环境。

> **关于商户号 `SUB_MCH_ID`**：目前是 `cloudfunctions/ptApi/index.js` 顶部的源码常量，留空表示支付未开通。
> 建议后续改为从环境变量读取（`process.env.SUB_MCH_ID || ''`，`_legacy/` 里的旧代码即是此写法），
> 这样商户号不会进入源码，仓库将来若要公开或加协作者时无需再处理。

## 数据库集合

| 集合名 | 存什么 |
| --- | --- |
| `pt_users` | 用户与身份（姓名 / 手机号 / 头像 / 角色） |
| `pt_applications` | 成团申请（待审核 / 已通过 / 已驳回 / 已撤回） |
| `pt_groups` | 拼团（进行中 / 已关闭） |
| `pt_members` | **成员台账**：谁拉的客、来源、参与时间、金额、付款状态、凭证 |
| `pt_pay_configs` | 收款账户配置（历史留档） |
| `pt_admins` | 管理员白名单 |
| `pt_blacklist` | 成团申请黑名单 |
| `pt_config` | 业务规则（建团上限、最低成团人数、联系管理员提示等） |

### 云存储权限

「云开发控制台 → 存储 → 权限设置」建议选择 **「仅创建者可读写」**。

代码中所有跨用户读取图片的场景（管理员查看他人凭证、成员查看收款码）都已经通过云函数生成临时链接实现，不依赖存储的公开读权限。

## 安全清单

上线前逐项确认：

- [ ] 云开发控制台删除环境变量 `ALLOW_SELF_GRANT`（关闭测试管理员自助入口）
- [ ] 所有数据库集合权限为「仅创建者可读写」，**不得**设为「所有用户可读」
- [ ] 云存储权限为「仅创建者可读写」
- [ ] 未开启云函数的「HTTP 访问服务」（开启后接口公网可达，且 `OPENID` 为空）
- [ ] 若已在源码中填入微信支付商户号 `SUB_MCH_ID`，**确认本仓库保持 Private**（或先改为环境变量读取）
- [ ] 确认免费版环境已升级为付费版（否则发布后第 15 天数据销毁）

## 开发约定

- 云函数只有 2 个：`ptApi`（用户 / 团长侧）、`ptAdmin`（管理端，含白名单鉴权）
- 数据库集合统一 `pt_` 前缀，避免与同环境其他业务冲突
- 云函数统一入参 `{ action, ...params }`，统一返回 `{ ok, msg, data }`
- 前端调用统一走 `utils/cloud.js` 的 `api()` / `adm()`
- 状态字典、金额与时间格式化统一放 `utils/format.js`，不在页面里硬编码
- 全局样式类库在 `app.wxss`，新页面优先复用，页面 `wxss` 只写差异
- 页面初始化统一用 `app.ready(cb)`，回调队列由 `app.js` 的 `flushReady()` 统一触发（登录失败也会触发）
- 修改 `cloudfunctions/` 下代码后必须重新「上传并部署」才生效

## 已知边界

| 项 | 当前实现 |
| --- | --- |
| 每个团长最多建几个拼团 | 1 个（管理端可改） |
| 最低成团人数 | 不限（管理端可改，仅作提示，不拦截） |
| 成员付款金额 | 由团长在成团时设置，成员可修改（自由金额） |
| 退款 | 不纳入线上流程，线下处理 |
| 分账 / 子账户 / 自动打款 / 自动结算 | **明确不做** |
